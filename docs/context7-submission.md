# Context7 submission readiness

## Intended source

- source type: public Git repository
- repository: `https://github.com/kunlunengine/core`
- branch: repository default (`main`)
- requested library identity: `/kunlunengine/core` if available
- curated entry point: [`docs/index.md`](./index.md)
- parser configuration: [`context7.json`](../context7.json)

Context7 accepts a public GitHub repository URL through its Add a Library interface. A root
`context7.json` can control metadata, inclusions, exclusions, agent rules, and version sources.
Claiming the library is a later operation: Context7 supplies the exact library URL and public key
that must be committed to the default branch. Do not add placeholder claim credentials.

## Indexing policy

The first index should contain user-facing documentation and package READMEs. It intentionally
excludes source, tests, generated output, launch copy, contributor recruitment, roadmaps, and
delivery plans. This prevents proposed v0.2-v0.4 behavior from being returned as an implemented
API and prevents tests or internal imports from outranking supported package-root examples.

The Git repository source does not require `llms.txt`. Add an `llms.txt` source only when Kunlun has
a canonical documentation website and can keep that website index current.

## Quality queries after indexing

The first index is acceptable only if it answers these from implemented documentation and states
the correct limitations:

1. How do I define a Kunlun service with a required capability and a dynamic Fetch route?
2. How do I switch a Kunlun application's build engine from Nasti to Vite?
3. Which build adapters currently expose HMR and SSR module loading?
4. How do I discover `app/` pages and validate a route-handler module?
5. Does Kunlun Next.js claim compatibility with Next.js applications and plugins?
6. Which default-branch packages are source previews rather than confirmed npm releases?

If results cite roadmaps as current behavior, first tighten exclusions or rewrite the nearest
status note; do not try to correct retrieval only through agent rules.

## Refresh workflow decision

Do not commit a refresh workflow during preparation. The official workflow needs both the final
library name and a `CONTEXT7_API_KEY`. After submission and claim, add a `main`-push workflow scoped
to documentation and package README changes, and verify that a missing secret cannot make normal
pull requests fail.
